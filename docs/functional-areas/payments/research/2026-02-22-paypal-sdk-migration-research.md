## BACKEND RESEARCH: PayPalCheckoutSdk -> PayPalServerSDK

### Deprecation Status of PayPalCheckoutSdk

| Attribute | Detail |
|-----------|--------|
| **Package** | PayPalCheckoutSdk v1.0.4 |
| **NuGet Status** | Deprecated -- marked as "legacy and no longer maintained" |
| **Last Updated** | September 21, 2021 (over 4 years ago) |
| **GitHub Repo** | Made private on April 29, 2024 |
| **Suggested Alternative** | PayPalServerSDK |
| **Will It Stop Working?** | The NuGet package remains downloadable, but the underlying REST APIs (Orders v2, Payments v2) are still active. The SDK itself is just an HTTP wrapper -- it will continue to function as long as PayPal's REST API endpoints remain available. However, no security patches or bug fixes will be issued. |

**Risk Assessment**: The SDK still works today because it's just an HTTP client wrapper around PayPal's REST APIs. The APIs themselves have not been deprecated. However:
- No security updates since 2021
- `PayPalHttp` dependency is also abandoned
- GitHub source code is no longer publicly accessible
- CI/CD could break if NuGet decides to delist the package
- No support for newer .NET features or security patches

### API Coverage Comparison

| API | PayPalCheckoutSdk v1.0.4 | PayPalServerSDK v2.2.0 |
|-----|--------------------------|------------------------|
| Orders API v2 | Yes | Yes (OrdersController) |
| Payments API v2 | No (separate SDK) | Yes (PaymentsController) |
| Vault/Payment Tokens v3 | No | Yes (VaultController, US only) |
| Transaction Search v1 | No | Yes (TransactionSearchController) |
| Subscriptions v1 | No | Yes (SubscriptionsController) |
| Webhook Management v1 | No | **No** |
| Webhook Verification | No (required Crc32.NET manual impl) | **No** |

**CRITICAL FINDING**: The PayPalServerSDK does NOT include webhook verification support. The SDK states it "currently contains only 5 of PayPal's API endpoints" and webhook APIs are not among them.

### Authentication Changes

**Old SDK (PayPalCheckoutSdk)**:
```csharp
// Old pattern - PayPalEnvironment + PayPalHttpClient
var environment = new SandboxEnvironment("clientId", "clientSecret");
var client = new PayPalHttpClient(environment);

// Execute requests
var request = new OrdersCreateRequest();
request.RequestBody(orderRequest);
var response = await client.Execute(request);
```

**New SDK (PayPalServerSDK)**:
```csharp
// New pattern - Builder + OAuth2 Client Credentials
var client = new PaypalServerSdkClient.Builder()
    .ClientCredentialsAuth(
        new ClientCredentialsAuthModel.Builder("clientId", "clientSecret").Build())
    .Environment(PaypalServerSdk.Standard.Environment.Sandbox)
    .LoggingConfig(config => config
        .LogLevel(LogLevel.Information)
        .RequestConfig(reqConfig => reqConfig.Body(true))
        .ResponseConfig(respConfig => respConfig.Headers(true)))
    .Build();

// Use controllers
var ordersController = client.OrdersController;
var result = await ordersController.OrdersCreateAsync(body);
```

**Key Configuration Differences**:
- Builder pattern instead of environment/client pattern
- Built-in IConfiguration support (JSON files, environment variables)
- Built-in logging configuration via Microsoft.Extensions.Logging
- Configurable HTTP timeouts (default: 100 seconds)
- Proxy support
- Custom HttpClient configuration

### Breaking Changes Summary

| Area | Old SDK | New SDK | Migration Impact |
|------|---------|---------|------------------|
| **Namespace** | `PayPalCheckoutSdk.*` | `PaypalServerSdk.Standard.*` | All imports change |
| **Client Creation** | `PayPalHttpClient` | `PaypalServerSdkClient.Builder()` | Constructor rewrite |
| **Environment** | `SandboxEnvironment`/`LiveEnvironment` | `Environment.Sandbox`/`Environment.Production` | Enum change |
| **Request Pattern** | Create request object, call `client.Execute()` | Call controller methods directly | Significant refactor |
| **Response Pattern** | `HttpResponse<Order>` | Direct model returns | Response handling changes |
| **Auth Token** | Handled internally | OAuth2 Client Credentials Grant (handled internally) | Similar concept, different config |
| **Dependencies** | PayPalHttp | APIMatic.Core, Newtonsoft.Json | Different dependency tree |

### Crc32.NET Package Analysis

**Current Usage**: `Crc32.NET` v1.2.0 is used for PayPal webhook signature verification. This is a manual implementation because neither the old nor the new SDK includes built-in webhook verification.

**With PayPalServerSDK**: The `Crc32.NET` package will **still be needed** because:
1. PayPalServerSDK v2.2.0 does NOT include webhook verification APIs
2. Webhook signature verification requires CRC32 computation regardless of SDK
3. The alternative is calling PayPal's verify-webhook-signature REST endpoint directly

**Options for webhook verification after migration**:
1. **Keep Crc32.NET** -- Continue local CRC32 verification (faster, no API dependency)
2. **Use PayPal's verify endpoint** -- POST webhook data to PayPal for server-side verification (simpler but adds latency and API dependency)
3. **Use ElCamino.PayPalCheckoutSdk** v2.5.0 -- Community fork with built-in `VerifyWebhookEvent.ValidateReceivedEventAsync()` (last updated December 2025, actively maintained)

**Recommendation**: Keep `Crc32.NET` for now, as local verification is faster and more reliable than server-side verification. Evaluate switching to PayPal's verify endpoint when/if PayPalServerSDK adds webhook support.

### .NET 10 Compatibility

PayPalServerSDK targets .NET Standard 2.0, which is fully compatible with .NET 10. The NuGet page explicitly lists .NET 10 compatibility. No issues expected.

### PayPal JS SDK v6 -- Important Future Change

PayPal has released JS SDK v6 (announced September 27, 2025) which is a major architectural change:

| Feature | JS SDK v5 (Current) | JS SDK v6 (New) |
|---------|---------------------|------------------|
| **Loading** | Script tag with client-id | Browser-safe client token |
| **Architecture** | Monolithic | Modular, component-based |
| **Bundle Size** | Larger | Significantly lighter |
| **Security** | Standard | iframe isolation, PCI DSS v4 |
| **Payment Methods** | All loaded | Load only what you need |

**Impact on react-paypal-js**: The `@paypal/paypal-js` underlying package already includes v6 types (since v9.0.0). The react-paypal-js v8.9.2 depends on `@paypal/paypal-js@9.0.0` which has v6 type support. However, the React components themselves have not yet been fully updated for v6's new component model.

**TypeScript Types for v6**: Available via `@paypal/paypal-js/sdk-v6` subpath.

## Implementation Considerations

### Backend Migration Path

**Phase 1: Preparation**
1. Audit all files using `PayPalCheckoutSdk` and `PayPalHttp` namespaces
2. Document all PayPal API calls (create order, capture, refund, etc.)
3. Document webhook verification implementation
4. Install PayPalServerSDK v2.2.0

**Phase 2: Client Migration**
1. Replace `PayPalHttpClient` with `PaypalServerSdkClient.Builder()`
2. Update environment configuration (Sandbox/Production)
3. Move credentials to new OAuth2 model
4. Update DI registration

**Phase 3: API Call Migration**
1. Replace `OrdersCreateRequest` with `ordersController.OrdersCreateAsync()`
2. Replace `OrdersCaptureRequest` with `ordersController.OrdersCaptureAsync()`
3. Update all request/response model mappings
4. Update error handling for new exception types

**Phase 4: Testing**
1. Test all payment flows in sandbox
2. Verify webhook verification still works
3. Test error scenarios
4. Update unit tests with new mocks

**Estimated Effort**: 2-3 days for a focused developer, depending on codebase complexity.

### Frontend Migration Path

**Immediate**: Bump `@paypal/react-paypal-js` from `^8.9.1` to `^8.9.2` in package.json. Run `npm install`. Test payment flows.

**Estimated Effort**: 15 minutes.

### Performance Impact

**Backend**:
- New dependency: `APIMatic.Core` adds ~150KB to published output
- New dependency: `Newtonsoft.Json` (if not already present) adds ~700KB
- Remove: `PayPalCheckoutSdk` and `PayPalHttp` (saves ~200KB)
- Net impact: ~+650KB (mostly Newtonsoft.Json if not already used)

**Frontend**:
- No meaningful change for v8.9.1 -> v8.9.2 (patch)

## Risk Assessment

### High Risk
- **Webhook verification gap**: PayPalServerSDK does not include webhook verification. Our existing Crc32.NET implementation must be preserved and potentially refactored to work independently of the old SDK.
  - **Mitigation**: Keep Crc32.NET package; extract webhook verification to standalone service class before SDK migration.

### Medium Risk
- **APIMatic.Core dependency**: The new SDK depends on APIMatic.Core, a code-generation framework. This adds an indirect dependency chain we don't control.
  - **Mitigation**: Pin version constraints; monitor APIMatic.Core for breaking changes.

- **Newtonsoft.Json conflict**: If the project uses System.Text.Json elsewhere, having both serializers can cause confusion.
  - **Mitigation**: Document which serializer is used where; APIMatic.Core handles its own serialization internally.

### Low Risk
- **Frontend minor version bump**: v8.9.1 to v8.9.2 is a patch with bug fixes only.
  - **Monitoring**: Run existing payment tests after bump.

- **PayPal REST API stability**: The underlying APIs (Orders v2, Payments v2) are stable and not deprecated.
  - **Monitoring**: Subscribe to PayPal developer newsletter for API changes.

## Recommendation

### Primary Recommendation: Migrate Backend to PayPalServerSDK v2.2.0
**Confidence Level**: High (85%)

**Rationale**:
1. **Security risk**: PayPalCheckoutSdk has received no security updates since September 2021 -- over 4 years without patches
2. **Official deprecation**: PayPal has marked the package as deprecated on NuGet and made the GitHub repository private
3. **Active replacement**: PayPalServerSDK v2.2.0 was published January 21, 2026 -- actively maintained with regular releases
4. **Expanded API coverage**: New SDK covers Orders, Payments, Vault, Transaction Search, and Subscriptions (old SDK only covered Orders)
5. **.NET 10 compatible**: Confirmed compatibility with our target framework

**Implementation Priority**: Next Sprint (not urgent since old SDK still functions, but should not be deferred beyond Q2 2026)

### Secondary Recommendation: Bump Frontend to v8.9.2
**Confidence Level**: High (95%)

**Rationale**: Trivial patch update with stale closure bug fixes for Card Fields.

**Implementation Priority**: Immediate (can be done as part of routine dependency updates)

### Future Consideration: PayPal JS SDK v6 + React Components
**Confidence Level**: Medium (60%)

**Rationale**: PayPal JS SDK v6 brings modular architecture, smaller bundles, and PCI DSS v4 compliance. However, the React component library has not yet been updated for v6's new paradigm. Wait for `@paypal/react-paypal-js` v9.x with full v6 support before migrating.

**Implementation Priority**: Future (monitor for react-paypal-js v9.0.0 release)
